CREST CHAT — ONE-TO-ONE AUDIO AND VIDEO CALLS
================================================

WHAT IS INCLUDED
----------------
- Audio and video calls between the CREST administrator and an individual student.
- Students can call the CREST administrator from the student chat.
- The administrator can call one student by selecting that student in the existing
  "Reply to" selector in the admin correspondence centre.
- Incoming call screen with Accept and Decline.
- Outgoing ringing state, missed/no-answer timeout, and decline feedback.
- Microphone mute/unmute, camera on/off, and end-call controls.
- Video starts with the camera OFF. Each participant can choose to turn it on.
- Calls are not recorded by this integration.

CURRENT WEBSITE INTEGRATION
---------------------------
The student root page (index.html) and administrator page (admin.html) already
load the LiveKit browser SDK and crest-calls.js. Keep these script references.
The calling code uses the existing CREST student/admin login sessions; it does
not create a second account system.

REQUIRED EDGE FUNCTION SECRETS
------------------------------
- LIVEKIT_API_KEY
- LIVEKIT_API_SECRET
- LIVEKIT_URL

LIVEKIT_API_SECRET must remain private in Supabase Edge Function secrets. Never
put it in HTML, browser JavaScript, GitHub, or a chat message. The function also
uses Supabase's built-in SUPABASE_URL and SUPABASE_SERVICE_ROLE_KEY environment
variables. The browser receives only short-lived LiveKit access tokens.

DEPLOYMENT
----------
The secure function source is:
  supabase/functions/crest-livekit-token/index.ts

Deploy to the MAIN CREST Supabase project with Verify JWT OFF because the
function verifies CREST's existing admin_check and student_me sessions itself:
  supabase functions deploy crest-livekit-token --no-verify-jwt

The function is currently deployed as an active version in the main project.
Do not deploy it to the separate CREST Examination project.

CALL WORKFLOW
-------------
1. Sign in as administrator on one browser/device and as a student on another.
2. Keep the relevant CREST chat page open so each user stays online in the
   LiveKit calling lobby.
3. Administrator: in the admin correspondence centre, choose one student in
   the "Reply to" selector. The audio/video call buttons become available when
   that student is online.
4. Student: open the student chat. The audio/video call buttons become
   available when the administrator is online.
5. The recipient sees an incoming call and can Accept or Decline.
6. Both participants allow microphone permission. In a video call, each
   participant can choose to turn on their own camera.
7. Either participant can mute, disable their camera, or end the call.

IMPORTANT LIMITATION
-------------------
The current CREST chat is a student-to-administrator correspondence system.
This implementation enables direct calls in both directions between the
administrator and one student. It does not add student-to-student messaging or
student-to-student calling.

TROUBLESHOOTING
---------------
- "Calling service is not configured": check the three LIVEKIT_* secrets in
  the MAIN CREST Supabase project.
- "Admin session could not be verified": sign out and back into the admin page.
- "Student session could not be verified": sign out and back into the student page.
- If no call buttons become active, confirm both users have the chat page open
  and the intended recipient is online.
- If the browser asks for microphone/camera access, allow it. If permission was
  denied earlier, update the site's permissions in the browser settings.
- Calls require HTTPS. GitHub Pages provides HTTPS.
- On mobile, keep the browser tab open during the call; closing or suspending
  the page can disconnect the calling lobby.
